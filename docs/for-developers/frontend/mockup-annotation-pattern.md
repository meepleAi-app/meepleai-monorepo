# Mockup Annotation Pattern (DS-17-1)

Each user-reachable Next.js route in `apps/web/src/app/.../page.tsx` should carry
a `@mockup` JSDoc annotation pointing to its canonical reference under
`admin-mockups/design_files/`. The annotation is a one-shot pointer — it does
not embed acceptance criteria (those live in the optional companion
`*.fidelity.{json,yml}` file, DS-17-4) — but it makes the mockup ↔ code link
discoverable from either direction.

**Sub-issue**: [#2069](https://github.com/meepleAi-app/meepleai-monorepo/issues/2069)
· **Umbrella**: [#2063](https://github.com/meepleAi-app/meepleai-monorepo/issues/2063)
· **Spec**: [`2026-06-09-mockup-to-app-drift-spec-panel-review.md`](../../../docs/superpowers/specs/2026-06-09-mockup-to-app-drift-spec-panel-review.md)

## Block shape

The injector prepends this JSDoc block to the top of each annotated file:

```tsx
/**
 * @mockup admin-mockups/design_files/sp4-dashboard.html
 *
 * MOCKUP-ANNOTATION marker — do not edit by hand.
 * Regenerated by: pnpm mockup-annotations:inject
 * Audit:          pnpm mockup-annotations:audit
 *
 * Ref: DS-17-1 #2069, umbrella #2063.
 */
```

The `MOCKUP-ANNOTATION` token is the **idempotency marker**: any file containing
it is treated as already annotated and skipped by `inject-annotations.mjs`.
Removing the marker (e.g. by hand-rewriting the JSDoc) makes the file appear
unannotated to the audit script.

## Workflow

### When you add a new route

1. Extend [`admin-mockups/MOCKUPS_INDEX.md`](../../../admin-mockups/MOCKUPS_INDEX.md)
   with a row mapping the new route to its canonical mockup file.
2. Run `pnpm mockup-annotations:inject` (dry-run) to preview the diff.
3. Run `pnpm mockup-annotations:inject --apply` to write the JSDoc block.
4. Commit the page.tsx change in the same PR.

### When you migrate or rename a mockup

1. Update the row in `MOCKUPS_INDEX.md` to the new filename.
2. Remove the existing JSDoc block from every affected page.tsx.
3. Re-run `pnpm mockup-annotations:inject --apply`.

### When the audit job flags drift

Run `pnpm mockup-annotations:audit` locally. The MD report at
`audits/2026-06-09-mockup-annotation-coverage.md` lists every uncovered route.
Add the missing rows to `MOCKUPS_INDEX.md` and re-run the injector.

## Scripts

| Script | Default | CI behaviour |
|---|---|---|
| `pnpm mockup-annotations:inject` | dry-run (no writes) | _not run in CI_ |
| `pnpm mockup-annotations:inject --apply` | writes files | _local-only_ |
| `pnpm mockup-annotations:inject --limit N` | process at most N mockups | _local-only_ |
| `pnpm mockup-annotations:inject --schema` | print mockup→route→file plan as JSON | _local-only_ |
| `pnpm mockup-annotations:audit` | inventory only, exit 0 | runs as **non-blocking** report (DS-17-1 phase 1) |
| `pnpm mockup-annotations:audit --threshold 80` | CI gate, exit 1 below 80% | _flip to this when coverage ≥ 80%_ |

## CI gate trajectory

| Phase | Coverage target | CI step |
|---|---|---|
| **DS-17-1 Wave 2** (now) | ~12% (Top-30 pilot) | `pnpm mockup-annotations:audit` non-blocking |
| **DS-17-1 sweep** (follow-up issue) | ≥80% | `pnpm mockup-annotations:audit --threshold 80` blocking |
| **DS-17 close** | 100% | `pnpm mockup-annotations:audit --threshold 100` blocking |

When the sweep PR lands, edit the `.github/workflows/ci.yml` step to add
`--threshold 80` and document the flip in CLAUDE.md § "🔒 Active Freezes".

## Anti-patterns

- ❌ **Hand-edit the JSDoc block**. The injector is idempotent and regenerable;
  manual edits will be overwritten on the next sweep. If a mockup is wrong,
  fix `MOCKUPS_INDEX.md` instead.
- ❌ **Remove the `MOCKUP-ANNOTATION` marker but keep the rest of the JSDoc**.
  The audit will mark the file as uncovered and the injector will prepend a
  second JSDoc block.
- ❌ **Annotate component files** (anything not under `apps/web/src/app/.../page.tsx`).
  Components are referenced indirectly via their parent route's annotation;
  layering annotations onto components causes false coverage signal.
- ❌ **Annotate API routes** (`app/api/.../route.ts`). These have no design
  surface; only user-reachable page.tsx files are in scope.
