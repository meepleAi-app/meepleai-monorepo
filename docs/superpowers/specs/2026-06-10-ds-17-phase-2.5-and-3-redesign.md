## 1. Context — perché redesign

Phase 2 v2 ha shipped 3 pilot stories (DashboardClient, LibraryContent, GameDetailView) con 4-3 stati ciascuno
seguendo pattern "intent coverage subset". User feedback post-merge ha rivelato 3 problemi strutturali:

1. **Mockup HTML è stage multi-frame side-by-side** (7-13 frames per mockup, axis matrix tab × view × bulk × drawer × state).
   Le pilot stories rappresentano solo subset arbitrario (es. Library 3 stories vs 13 mockup frames).
2. **Mockup design-forward vs componente corrente mismatch** — `sp4-dashboard.jsx` dichiara esplicitamente
   "REFACTOR-FORWARD" con 5 entity sections, ma `DashboardClient.tsx` post Asse C #1898 ha 4 priority slots.
   Story Default rende current MA mockup è obsolete target. Silent divergence.
3. **Mobile viewport zero coverage** — solo Desktop 1440x900 nelle pilot stories; mockup ha PhoneShell (375px) PRIMA del Desktop.

Plus: **IntlProvider decorator blocker** (Phase 2 v2 carry-over) — pilot stories renderano "intl object missing" error
wall, snapshot suite non eseguibile.

Senza redesign, Phase 3 contributors riprodurrebbero questi 3 problemi × 67 page-mock + 48 component-mock
= ~30-40% coverage matrix gap + 20-30% silent design-intent mismatch + zero mobile.

### 3.1 IntlProvider decorator fix

Root-cause investigation `.storybook/preview.tsx` decorator integration. Candidate hypotheses:
- Decorator order (`withThemeByClassName()` may intercept before custom Story decorator)
- `'use client'` boundary del `IntlProvider` component
- Webpack runtime chunk init order in `@storybook/nextjs` builder
- Module resolution differences vs vitest alias config

**Approach**: instrument console.log debugging via Storybook dev, identify failure point, fix via:
- (a) Direct `ReactIntlProvider` from `react-intl` con messages stub inline, OR
- (b) Use `@/components/providers/IntlProvider` (already-tested production wrapper), OR
- (c) Alternative: dynamic import `next-intl` mock alias compatibili con Storybook builder

Budget: ~1gg. Escalation path documented in §6 Phase 4 follow-up.

### 3.2 fidelity.json schema extension

Estende `apps/web/scripts/mockup-annotations/validate-fidelity.mjs`:

```ts
acceptance: z.object({
  // ... existing fields preserved (visual_diff_max_px, etc.)

  design_intent: z.enum(['current', 'forward-refactor', 'forward-refactor-obsolete'])
    .default('current')
    .describe('Mockup intent vs codebase corrente.'),

  viewports: z.array(z.enum(['desktop', 'mobile']))
    .min(1)
    .default(['desktop'])
    .describe('Snapshot viewports per story.'),

  obsolete_tracking_issue: z.string()
    .regex(/^#\d+$|^$/, 'Format: #1234 or empty')
    .default('')
    .describe('GitHub issue # tracking mockup rewrite OR component rollback.'),
})
```

Cross-reference check: `design_intent = 'forward-refactor-obsolete'` requires `obsolete_tracking_issue` set.

Tests: +3 vitest cases (enum validation + obsolete required + viewports default).

## 5. argTypes matrix story pattern (esempio canonico)

**`LibraryContent.stories.tsx` v2** (post Phase 2.5 rewrite):

```tsx
/**
 * @mockup admin-mockups/design_files/sp4-library-desktop.html
 *
 * Stage axis: tab × view × bulk × drawer × state (5 axis, 13 frame canonical).
 * Stage frame exports mirror exact label dal mockup JSX twin (`Frame09_AllGridRail`).
 */
const meta: Meta<typeof LibraryContent> = {
  title: 'Pages/SP4/Library / Mockup Matrix',
  component: LibraryContent,
  parameters: { layout: 'fullscreen' },
  argTypes: {
    tab: { control: 'select', options: ['all', 'game', 'agent', 'player'] },
    view: { control: 'select', options: ['grid', 'list'] },
    bulk: { control: 'boolean' },
    drawer: { control: 'boolean' },
    state: { control: 'select', options: ['default', 'empty-first-run', 'empty-filtered', 'loading', 'error'] },
  },
  args: { tab: 'all', view: 'grid', bulk: false, drawer: false, state: 'default' },
};

function mswForState(state: string) { /* ... handlers per state */ }

export const Frame09_AllGridRail: Story = {
  name: '09 · Desktop · All · Grid 4-col + Activity rail',
  args: { tab: 'all', view: 'grid', state: 'default' },
  parameters: { msw: { handlers: mswForState('default') } },
};

export const Frame10_GiochiGridBulk: Story = {
  name: '10 · Desktop · Giochi · Grid + Bulk select',
  args: { tab: 'game', view: 'grid', bulk: true, state: 'default' },
  parameters: { msw: { handlers: mswForState('default') } },
};
// ... 13 frame exports total
```

```ts

  { slug: 'pages-sp4-library-mockup-matrix--frame09-all-grid-rail', file: 'library-09-all-grid-rail.png' },
```

**Vantaggi pattern**:
- 1 story FILE (non 13 separate) → DRY
- Designer review via Storybook controls toolbar (manual matrix exploration)
- Snapshot tests programmaticamente iterano frames canonical (1:1 mockup stage)
- Phase 3 contributor copia pattern verbatim, change only `argTypes`, `args`, `FRAMES` list
- argTypes inferrable dal mockup JSX twin (`stateOverride`, `variant`, `initialTab` props)

## 8. Anti-patterns (NON fare)

- ❌ **Multiple story files per mockup**: DEC-P3-3 mandates 1 file con argTypes matrix.
- ❌ **Skip design_intent audit**: silently migra mockup obsolete = drift garantito.
- ❌ **Force Mobile viewport per ogni mockup**: snapshot count esplode 2x; opt-in is the lock.
- ❌ **Hardcode args/state nelle story `args`**: usa `argTypes` controls, defaults centralizzati in `meta.args`.
- ❌ **Story name divergence dal mockup label**: story name MUST mirror exact mockup frame label
  (es. `'09 · Desktop · All · Grid 4-col + Activity rail'`) per pixel-faithful cross-ref.
